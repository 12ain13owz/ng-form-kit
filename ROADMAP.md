## What it is

`@12ain13owz/ng-form-kit` is the owner's own set of Angular form fields, shared by their apps
(first user: [SplitSlip](https://github.com/12ain13owz/splitslip)). Every field:

- is bound like a native input (`formControlName`, `[formControl]`, `ngModel`),
- shows label, hint and the first validation error, with messages the app controls,
- is built on spartan/ui and styled with Tailwind v4, so it matches the app's spartan theme,
- has a Storybook story with a real `FormControl`.

## How we build a field

**One field (or one small group) = one branch = one PR.**

1. Field in `src/lib/fields/<field>/<field>.ts`, following [`AGENTS.md`](AGENTS.md).
2. Stories in `<field>.stories.ts`: default, hint, error (touched), disabled, read-only, and one in
   a `FormGroup` with `formControlName`. Check them in Storybook (`npm run storybook`).
3. Export it from `public-api.ts`.
4. `npm run lint`, `npm run typecheck`, `npm run build`, `npm run build-storybook` all pass.
5. Update this file: move the field to ✅, note decisions and known issues.

Tests (Vitest) come in one pass once a field's API is stable, not while it is still changing.

## Release (GitHub Packages)

- `.github/workflows/release.yml` runs on a `v*` tag: build, then `npm publish` from
  `dist/ng-form-kit` to `https://npm.pkg.github.com` with the workflow's `GITHUB_TOKEN`.
- Version: set `version` in `projects/ng-form-kit/package.json`, commit, tag `v<version>`, push the
  tag. SemVer; while `0.x`, a minor bump may break the API.
- An app installs it with an `.npmrc` that points the scope at GitHub Packages, and a token with
  `read:packages` (README → Install).

## Locked decisions

- **Own repo, own package:** not copied into apps. Apps install a released version.
- **Angular 22, standalone, signals, OnPush.** Selector prefix `nfk-`.
- **Fields forward the control** (`forwardControl()`): the field takes the `NgControl` on its own
  element, gives it a no-op value accessor and binds the same `FormControl` to its inner element.
  No hand-written `ControlValueAccessor` per field, so touched, disabled, validation and spartan's
  error state behave exactly as on a plain input.
- **No i18n library in the kit.** English defaults; the app passes `errorMessage` (and a
  `language` signal) to `provideFormKit`. `withMessage(validator, keyOrText)` sets a per-field
  message.
- **spartan helm lives in `src/lib/ui/`** as the spartan CLI writes it, with its
  `@spartan-ng/helm/*` imports rewritten to relative paths (`npm run helm:fix`), because
  ng-packagr doesn't rewrite path aliases. `@spartan-ng/brain`, `@angular/*`, `@ng-icons/*`,
  Tailwind and `tw-animate-css` are **peer dependencies**; `clsx`, `tailwind-merge` and
  `class-variance-authority` ship as dependencies.
- **No theme in the package.** The app's spartan theme styles the fields; Storybook has its own
  default theme in `.storybook/styles.css`.
- **Money in satang** (integers) wherever a field holds money.
- **Field look (owner, 2026-11):** label `floating` by default (inside the box, moves onto the top
  border on focus or with a value) or `stacked` (above). Under the box one compact row (4px below
  it): the error on the left, the hint on the right by default (`hintPosition: 'end'`); with
  `'start'` the error replaces the hint while it shows. Both defaults are set app-wide in
  `provideFormKit` and per field by inputs. A floated label sits on `--nfk-field-bg` (default
  `--background`), which a parent sets on cards.
